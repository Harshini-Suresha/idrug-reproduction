iDrug, re-implemented from scratch — benchmarked on the authors' real data

iDrug: Integration of drug repositioning and drug-target prediction via cross-network embedding (Chen, Cheng & Li, PLoS Comput Biol 2020) predicts drug–disease and drug–target links with a cross-network matrix factorization. This project rebuilds the model, ports the authors' MATLAB solver line-by-line, and implements five baseline methods from their papers — then benchmarks everything on the authors' released CTD + DrugBank matrices (1,321 × 3,966; 946 × 3,610; 469 shared drugs) and their smaller Gottlieb gold-standard dataset. Every number on this page regenerates from the committed scripts.

The fine print

Limits — read before citing anything here

Protocol ≠ the paper's protocol

My pair CV hides 1/5 of links and samples negatives uniformly, following the paper's description — but the split code, the exact negative draw, and the fold bookkeeping are mine. Cold-start P@k also averages over held-out rows differently from their scenario code. Treat headline gaps as indicative.

Uniform negatives saturate

On CTD drug–disease the popularity baseline alone is competitive with everything, because degree is signal when negatives are uniform. A harder, degree-matched negative draw would likely reorder the table. This is a known failure of the benchmark as published, not of any one method.

Model ≠ paper

idrug() is an independent reading of Eq. 1–3: consistency via drug–drug Gram matrices, one shared rank (90) rather than 90/70, weight w not w². The official port is line-by-line but verified only against the authors' printed new-drug example, not the full paper tables.

Baselines are re-implementations

GRMF and RLS-Kron follow their papers with default hyperparameters (no tuning); the bi-random walk is a simplified stand-in for MBiRW. TL-HGBI is missing. Any baseline here is a floor of unknown height, and tuning could move the ranking.

One seed

The real-data tables are a single run per domain (seed 0, s.d. across folds). The synthetic benchmarks used 3 seeds; the real-data runs do not, because each full pass costs minutes to hours on one CPU.

Not biomedical advice

Predictions from this pipeline are unvalidated computational hypotheses. Nothing here has been checked against assays, literature, or clinical data — the paper's own top prediction lists (validTop20gold.csv) ship with the authors' repo if you want to compare.

Reproduce

Everything on this page, from a clean clone

# 1 · install (numpy, scipy, pandas, scikit-learn — that's all)
pip install -r requirements.txt

# 2 · get the authors' real data (their repo is ~290 MB; not shipped here)
git clone --depth 1 https://github.com/Case-esaC/iDrug iDrug

# 3 · the benchmark + sweeps behind this page → results_real.json, sweeps_real.json
python run_real_all.py --mat iDrug            # full run, hours on one CPU core
python run_real_all.py --mat iDrug --quick    # 2-fold, 3-iteration smoke test

# 4 · rebuild the data file behind this website, then open docs/index.html
python make_site_data.py

# 5 · the same script also runs on the CSV layout (data/README.md)
python run_real.py --mat iDrug --official --rank 90 --r2 70 --w 0.3 \
  --alpha 0.001 --beta 0.001 --gamma 0.001 --folds 5 --reps 1

The synthetic generators (gen_datasets.py, run_all.py) remain in the repo as fast pipeline tests — sizes match the paper, but nothing synthetic feeds this page.
